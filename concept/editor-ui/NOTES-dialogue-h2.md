# Dialogue H2 notes (branch feature/npc-dialogue-popup)

## What was done
- Data (per placed NPC, `ActorSpec` in `src/game/types.ts`, map file `actors[]` in `src/game/mapFormat.ts`): `friendly?: boolean`, `dialogue?: { library, entry }`, `portrait?: string` (shared still id), `shop?: string`. All optional, old maps load unchanged; strings are type-checked and empty values dropped on load. Type default: `ActorType.friendly` (smith1 has it); a placement's own `friendly` (true or false) wins (`isFriendlySpec`).
- Catalog: `src/game/dialogueCatalog.ts` (`getDialogue`, `getDialogueLibraries`, `useDialogueLibraries`) over the pure `src/game/dialogueCatalogCore.ts` (`buildDialogueCatalog`, layers: bundled `src/dialogues/*.twee` via `import.meta.glob`, then the IndexedDB drafts, later wins by id; parsed once and rebuilt only when drafts change). `src/dialogues/void-fantasy.twee` = copy of the sample. Test: `npx tsx src/game/dialogueCatalog.test.ts`. `dialogueDrafts.ts` got an exported `subscribeDialogueDrafts`.
- Friendly behaviour (`src/game/actors.ts`, one small branch in `stepActors`): `ActorState.friendly`; wanders (50% idle, else one step, pause after each step) within 3 cells (Chebyshev) of its start, never through a door, wall, closed cell or another actor, with the existing walk rows; a patrol route (2+ cells) is walked instead. Never wakes/dormant (`actorWake`), never hostile (lockdown, stance, hits), skipped in actor-vs-actor fights (both ways) and by the crew's turrets, not in `targetsInReach`, not an aim target (`updateAimFrame`), shots go through it (`shoot`), no scanner outline. It still blocks the party's path (not `passive`).
- Talking: `useGameState.faceActor(id)` (`faceParty`) turns the NPC to the party when the dialogue opens; the world and game clock are paused while it is open (like a modal message), so it stands still.
- Interaction: `Interaction` kind `dialogue` (`interactions.ts`; extra optional `actorId` = index in the map's actors), `InteractionTarget` kind `actor`, `actorInteraction(spec, index)` (cached per spec so Use can match its candidate), `readInteraction` parses `dialogue` too (so props/walls could carry one by hand-editing). `GameViewport.tsx`: `interactable()` maps an actor mesh to the target (in edit mode it is ignored), the ray test uses the sprite alpha, `useInteraction()` considers friendly NPCs with a dialogue (reach 1.8, 55 degree cone like props). Click path is the existing pointer path.
- Popup: `src/components/DialoguePopup.tsx` (portrait or silhouette, text, choices as buttons, keys 1-9, Up/Down + Enter, Esc closes, Tab swallowed, focus restored). `@end` shows the text then only the "Goodbye" button; `@shop` shows `[Shop: <id> - the shop window comes in a later step]` (own shop: the NPC's `shop`, else "own shop") and the dialogue continues. Missing library/entry shows a red error text. `App.tsx` routes `dialogue` events to it and its own keys; the old Esc/Enter handler skips dialogues.
- Editor: "Talk" group in `ActorFields.tsx` (Friendly checkbox; Dialogue select from `useDialogueLibraries`, Entry select from that library; Portrait select = shared stills with purpose portrait; Own shop id). Choosing a dialogue switches Friendly on (offered, can be unticked). Missing library/entry/portrait show as "(missing)". `validate.ts`: warning `missingDialogue`. `EventFields.tsx` shows a dialogue event read-only with Remove.
- smith1: new type (mage1 sheet as placeholder, name "Smith", moveMs 1800, waitMs 2600, damage 0, friendly), registered in `FANTASY_ASSETS`. Actor names are English only in this code base (no hu name mechanism), so "Kovács" is not shown anywhere. Shipped maps are untouched.
- i18n en + hu: keys `events.dialogue`, `dialogue.popup.*`, `talk.*`, `minimap.problem.missingDialogue` in `src/i18n/{en,hu}/dialogue.ts`.

## How to test (browser)
1. Editor, fantasy world map: NPC tool, place `smith1` (NPC select in the inspector), open the "Talk" group: pick Dialogue `void-fantasy` (Friendly ticks itself), Entry `Start Smith`; optionally a Portrait and a shop id. (The Problems list shows a warning if the library/entry is wrong.)
2. Leave the editor and walk up to him (within ~1.8 units, facing him). He should wander slowly within 3 cells and idle between steps, not attack, not be a target when aiming (1-9 weapons) and not outlined by the enemy scanner.
3. Press Space (or click him): the popup opens, he turns to you, the world stops. Keys 1-9 / Up-Down + Enter pick; "Smith buy" shows the `[Shop: smith-shop ...]` line; "Goodbye Smith" ends with a Goodbye button; Esc closes at any time and he walks on after a moment.
4. Edit the library in Assets > Dialogues (re-import the same id) without rebuilding: the new text is used at the next talk. Set the library to a name that does not exist: the popup shows the red error text.
