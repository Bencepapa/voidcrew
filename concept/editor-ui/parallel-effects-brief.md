## Data model
- Smoke entries get an `effect?: "smoke" | "fire" | "mist" | "motes" | "petals" | "fireflies"` field. Legacy booleans stay readable and keep their look: `fire: true` -> "fire"; `petals: true` (no `effect`) -> **"motes"** (the old glowing squares, so `src/maps/fantasy/fantasy.json`'s three petal emitters look exactly as before). The parser normalises to `effect`; the editor writes `effect` (and drops the legacy booleans) once an emitter's effect is edited. `decorative`, `chance`, links, `blow`, `density`, `size`, `color`, `pos` keep their meaning for all effects.
- A map-level `weather?: { type: "rain" | "snow"; intensity?: number /* 0..2, default 1 */; wind?: [number, number]; indoors?: boolean }` block in the map file (and in `GameMap`), for rain and snow: not an emitter but the deck's weather. It falls only where there is open sky above (cells whose ceiling texture is "sky", see `src/game/map.ts` / `GameViewport.tsx`'s sky handling) unless `indoors: true` (then it falls everywhere: for a story that wants rain inside a ruin). Part of the map's `structureKey` or applied live like smokes - your choice, but changing it in the editor must not rebuild the whole scene if you can avoid it (see how smokes are applied in place with `applyLightsRef`).
- Backward compatibility is a must: old map files load and look the same; `npx tsc --noEmit` clean.

## Rendering (new files under `src/render/`, keep each system small and cheap on phones; honour `settings.particleQuality` and `particleEvery` like the existing particles do)
- `weather.ts`: rain and snow as ONE camera-following particle volume (a few hundred instances at most, scaled by quality and intensity), wrapped around the camera, only drawn where the cell above is open sky. Rain = thin elongated, slightly slanted streaks (additive/alpha, fog-aware), snow = soft round flakes with gentle drift and slow rotation. Splashes/ripples are optional (skip unless cheap). They must not fall through roofs or inside rooms.
- `mist` (two options, selectable per emitter via a `style` or two effects "mist" and "ground fog" - your choice, document it): (a) *standing mist*: reuse `smoke.ts` puffs configured not to rise: large, low, thin, slow, long-lived, no ceiling gathering, soft edges; (b) *ground fog*: a cheap layered effect (a few big soft translucent planes/sprites hugging the floor over the emitter's area, slowly sliding), no per-puff physics. Plus tell in the final report whether the map's existing fog (`fogColor`, view distance) is enough as a "global fog" and how a `render.fogDensity` could be added (do not add it unless trivial).
- `petals.ts` (extend, keep the old look available as "motes"): textured petals = small quads (instanced or points with a texture atlas) with a petal texture, tumbling/fluttering rotation, drifting with the emitter's wind. Textures live in `public/particles/` (NEW folder): generate 3 small pixel-art-style petal/leaf PNGs (e.g. `petal1.png` pink, `leaf1.png` green, `petal2.png` white; 16x16 or 32x32, transparent background; any simple generation script is fine, commit the PNGs and the script under `scripts/`), and make the sprite list data-driven (an artist adds a PNG and it can be chosen; read the folder via an `index.json` like `public/decals/index.json` does). The emitter's `color` tints the sprite.
- `fireflies.ts`: glowing soft dots wandering erratically (smooth random walk in a small volume around the emitter), pulsing on and off at their own rates, additive blending, warm yellow-green by default, tintable with `color`; a handful per emitter; `chance`/`decorative` etc. as for the others.
- Wiring in `GameViewport.tsx`: only where particle emitters are built/updated/disposed (the `smokes` -> emitter code, `applySmoke`, the per-frame `update`, the editor layer hiding "smoke", the dispose paths) - minimal, readable edits, no changes elsewhere in that file. Weather updates every frame with the camera position. Hidden together with the "smoke" editor layer.
