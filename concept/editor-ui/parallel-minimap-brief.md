## Part 1 - floor textures on the minimap
Each open cell of the (editing and normal) minimap shows its floor's texture instead of a flat colour: SVG `<pattern>` per texture set (defined once in `<defs>`, shared by all cells; each cell shows the texture once, scaled to the cell; keep pixel-art crisp with `image-rendering: pixelated`), with the existing height shading kept as a translucent tint over it (raised lighter, sunken darker) so heights stay readable. The texture set of a cell = the same rule the 3D scene uses: `map.floorAt?.(x, y)` if it names a known set, else the deck's `map.textures?.floor`, else the default floor of the world (find how `GameViewport.tsx` picks `DEFAULT_FLOOR`; do not import from GameViewport if it creates a cycle: read the value and use `TEXTURE_SETS` from `src/render/textureSets.ts`, `isTextureSetId`). Doors, ladders, bridges, windows, restricted shading, walls, the party arrow and the start marker keep working on top. A small toggle in the editing minimap's header (i18n'd, state kept in the component) switches the textures on/off (default on). Must stay fast on a 64x64 map (no per-cell `<image>` elements).

## Part 2 - object markers and the category colours
`src/editor/categoryColors.ts` exports one table: the outline/marker colour per element category (the same palette will later colour the 3D outlines and the asset tree, so choose distinguishable colours that also read on dark and on light/grey backgrounds): prop, decal (decals are on surfaces, show them as small ticks on the cell edge), item, npc, light, smoke, exit, start, door, ladder, bridge, restricted, chanceWall. Export `CATEGORY_COLORS: Record<Category, string>` and the `Category` type.
In the editing minimap (the `edit` variant) draw small markers for the map's placed things, in those colours: props (`map.props`, a square, wall-hung ones on the cell edge), lights (`map.lights`: a ceiling lamp = small circle in the cell, a free-standing one at its spot), NPCs (`map.actors`, a dot with a short facing tick), items (`map.items`), smoke emitters (`map.smokes`), exits (`map.exits`), chance walls (`map.chanceWalls`). Optional props on the `edit` object: `hiddenCategories?: ReadonlySet<string>` (those are not drawn), `onMarker?: (category: string, index: number, alt: boolean) => void` (a click/right-click on a marker calls it instead of the cell click; hit area a bit bigger than the marker; when absent markers are not clickable). Markers must not make a click-drag block selection or the cell click unusable.

## Part 3 - map validation ("Problems")
`src/editor/validate.ts`: a pure `validateMap(map: GameMap): Problem[]` with `Problem = { severity: "error" | "warning"; code: string; cell?: Vec2; key: string; params?: Record<string, string | number> }` where `key` is an i18n key under `minimap.problem.*` (English + Hungarian texts in the minimap i18n files). Checks (look at the data to see what exists; skip a check that the data model cannot support and say so in your final report): no start / start inside a wall; no exit on the map; open areas the party cannot reach from the start (use the real movement rules from `src/game/movement.ts` / the step height limits - read how grid movement decides a step; doors, ladders and bridges count); something standing in a wall cell (prop, NPC, item, light, smoke); door lock key / code with no source of that key on the map (terminals, decals with `terminal:<id>` actions, triggers: look at `Linked`, `Lock`, `Terminal`, `Trigger` types); `with` / `without` link ids that no object defines; two ceiling lights in one cell; a prop/decal on a surface that does not exist. Keep each check small and independent.
`src/editor/ProblemsPanel.tsx`: `ProblemsPanel({ problems, onGoto })`, a compact list (errors red, warnings amber, count in the header, "no problems" state), click a row -> `onGoto(cell)`. Compact, minimal styling (dark, small type, no game-UI look), all text via `t()`.
`scripts/validate-maps.ts`: run with `npx tsx scripts/validate-maps.ts`: loads every map in `src/maps/**` (see how `src/editor/mapStore.ts` / `src/game/map.ts` load them; the script may need `import.meta.glob`-free loading: read the JSON files with fs and parse with `parseMap`) and prints the problems per map in plain text. Report what it finds on the existing maps (real bugs in our maps are valuable: list them in your final report, do not fix the maps).
